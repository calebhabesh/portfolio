The original brain scan, through each stage

The real T1 post-contrast MRI slice used in the original capstone demonstration. Keep the original image in view while inspecting what each filter produces.

Read the pipeline transcript
  1. 0–4 seconds · Input. Import the original capstone T1 post-contrast brain MRI from DICOM.
  2. 4–8 seconds · Normalization. Map the fixed input intensity range into 0.5–2.5.
  3. 8–12 seconds · Clipping. Bound intensities after normalization.
  4. 12–16 seconds · Median filtering. Suppress isolated intensity variation with a seven-pixel window.
  5. 16–20 seconds · Sharpening. Enhance local contrast with the shared pipeline parameters.
  6. 20–24 seconds · Region growing. Dimension-based seeds and fixed intensity bounds form an experimental mask.
  7. 24–28 seconds · Erosion. A separate branch shrinks the region-growing mask.
  8. 28–32 seconds · Dilation. Expand the un-eroded region-growing mask to produce the batch output.

FAST supplies the filters and segmentation operations. Erosion and dilation are independent branches; tumor-segmentation accuracy has not been evaluated against annotated masks.

Scan source: Schmainda, K. M., & Prah, M. (2018), Data from Brain-Tumor-Progression, TCIA. Dataset citation.

One GPU producer, concurrent export workers

FAST provides the image algorithms and OpenCL acceleration. The application owns input discovery, pipeline integration, OpenMP scheduling, output export, and verification.

Producer · thread 0

Import DICOM → preprocess → region grow → dilate → read the completed pixels back to host memory. Retain compiled kernels between slices.

OpenMP export tasks

Convert completed host images into grayscale previews and write lossless masks and PNGs while the producer processes the next slice. Wait at each batch boundary to bound memory.

Each slice has its own result slot. A failed input or export fails the run, and every benchmark output must match the sequential reference.

Repeated measurements

3.15× throughput with eight OpenMP threads. Median whole-program time fell from 28.92 to 9.18 seconds for the same 460-slice processing-and-lossless-export workload, a 68.2% reduction in elapsed time.

All 30 runs, including warmups, completed every slice. Each run's 460 PGM masks and 920 PNG previews matched the sequential reference byte for byte by SHA-256.

Control: processing without exports

With preview and mask-file exports disabled, one-worker and eight-thread medians were 8.68 and 8.63 seconds. That difference falls within the observed ranges and timing resolution. Additional threads did not establish a useful gain in GPU processing alone.

The 3.15× result therefore applies to the complete processing-and-export workflow: CPU conversion and lossless export tasks run concurrently and overlap the single GPU producer. It does not measure faster FAST segmentation kernels.
