Doorlink

Embedded systems · self-hosted IoT

A self-hosted smart doorbell built on a hand-assembled ESP32-S3 PCB and Raspberry Pi gateway. A button press wakes the device, captures a visitor image, sends a notification, and returns to deep sleep; the dashboard also supports stored, turn-based voice replies.

  • ESP32-S3
  • Spring Boot
  • Raspberry Pi
  • KiCad
Notes +

Custom hardware: The Rev C board combines an OV5640 camera, microphone, speaker, battery power path, and routed KiCad design.

Device-to-dashboard flow: ESP-IDF firmware sends events to a Spring Boot gateway with PostgreSQL, MinIO media storage, MQTT, and a Next.js interface.

Validation boundary: The battery-powered capture/upload/sleep path and audio paths have run on hardware. Final hardened-firmware retest and closed-enclosure current measurements remain.

Transit intelligence · full stack

A map-first reliability dashboard for TTC and GO/UP riders. It brings service alerts, planned closures, station arrivals, and saved-commute impact checks into one view, while labeling stale, scheduled, unavailable, and demo data honestly.

  • PostGIS
  • Redis
Notes +

File Sync

Distributed systems · local-first files

A Go peer-to-peer file sync daemon for trusted Linux devices. It keeps causal version history, transfers content-addressed chunks over authenticated peer connections, and exposes concurrent edits for deliberate resolution through a local interface instead of silently replacing a file.

  • Go
  • SQLite
  • mTLS
  • Linux
Notes +

Causal history: Immutable version heads and vector clocks preserve offline edits; the local UI lets users inspect history and conflicts.

Recovery: SQLite metadata, atomic chunk staging, and fault-injection tests exercise crash durability.

Real workflow: A workstation, Raspberry Pi, and cloud relay were used in a three-host pilot; the repository also has a local multi-process demo.

CourtLoad

NBA analytics · data engineering

An NBA player comparison and analytics dashboard built from three historical regular seasons. It lets users compare player form, usage, and matchup context with source-traceable data and uncertainty informed by time-safe evaluation.

  • Python
  • PostgreSQL
  • dbt
  • Next.js
Notes +

Reproducible data: Python ingestion, PostgreSQL, and tested dbt models turn pinned schedules and box scores into dated player and opponent views.

Useful comparison: A Next.js dashboard and FastAPI service show side-by-side trends, game logs, and matchup context.

Honest modeling: Out-of-time evaluation kept the EWMA baseline after a gradient-boosted challenger failed promotion gates; the evaluation is shown to users.

  • OpenMP
  • FAST
  • DICOM
Notes +

Pipeline: DICOM ingest, preprocessing, segmentation, morphological operations, and export were integrated with FAST.

Parallel design: OpenMP distributes scan batches across CPU threads.

Evaluation: Benchmark tooling compares execution modes; present a numerical speedup only if the result and personal contribution can be cited.
